# Telos v0.11 Migration Design

## Objective

Migrate the repository from its split Telos 0.8.2/0.9.0 setup to one exact
Telos v0.11.0 toolchain. The checked-in model, the replayable development
story, generated agent guidance, CI workflows, documentation, and sealed lock
must all agree on v0.11.0 while preserving Momo's existing behavior, identifiers,
and test evidence.

Upstream tag inspection on 2026-08-25 established v0.11.0 as the latest
published `hugues31/telos-sdd` release. This migration therefore resolves the
user's "latest, otherwise 0.11" instruction to the immutable v0.11.0 tag.

## Current State

The repository is clean and its checked-in specification already uses the
Telos 0.9 context/capability layout. Telos 0.11.0 parses that specification and
reports a coherent model with 12 implemented active intents, 17 proved
scenarios, and two constraints.

Compatibility is incomplete in four places:

- current documentation and sealed-state workflows install Telos 0.9.0;
- the replay and bootstrap prompt install Telos 0.8.2 and construct the removed
  flat specification layout;
- the checked-in Claude skills predate the context/capability boundary rules
  and v0.11 challenger domain-language review;
- `telos/telos.lock` identifies Telos 0.9.0 as its sealing tool.

Changing version strings alone is invalid because v0.11 rejects the flat
layout used by the replay. The replay itself must become a v0.11 story.

## Scope

The migration changes:

- exact Telos version pins and explanatory prose in `README.md`;
- all replayed commands, payloads, paths, and expectations in `prompts/`;
- the GitHub Actions installers in `demo.yml`, `demo-gif.yml`, and `telos.yml`;
- the three generated Claude skill files under `.claude/skills/`;
- the Playwright tour and its integration assertions in `tools/record_demo.py`
  and `tools/test_record_demo.py`;
- the sealed tool identity and digest in `telos/telos.lock` through the Telos
  CLI;
- the generated `docs/demo.gif` produced by the upgraded tour;
- replay validation so a clean v0.11 reconstruction is compared with this
  repository again.

The migration does not change Python application behavior, scenario meaning,
intent wording, identifiers, constraints, test assertions, tag names, or the
configured agent host. The repository remains configured for Claude only;
adding Codex integration is outside this migration.

`docs/demo.mp4` remains an ignored local/CI artifact. `docs/demo.gif` is
regenerated by the same recorder used in `demo-gif.yml`; the binary asset is
never edited by hand.

## Replay Architecture

The eight-prompt narrative remains intact: bootstrap, five cumulative product
changes, the drift incident, and the open-ended challenge. The five product
changes retain `CHG-0001` through `CHG-0005`, scenario IDs `SCN-0001` through
`SCN-0017`, and release tags `v0.0.0` through `v0.5.0`.

The first change establishes the `pet` bounded context and the `pet/lifecycle`
and `pet/care` capabilities before adding their owned vocabulary and intents.
Later pet behavior is staged directly into its final owner rather than created
in a legacy global namespace and moved afterward.

The fifth change establishes the `terminal` context and
`terminal/portrait` capability. It adds the terminal-owned view vocabulary and
portrait intent, then stages the context-map dependency from `terminal` to
`pet`, mapping `pet/Pet` to `terminal/PetView`. The project-level architecture
constraint remains owned by `project`; the vitals constraint remains owned by
`pet`.

Every v0.11 entity payload includes its explicit owner. Notion and intent edits
use qualified references wherever v0.11 requires them. Bindings remain split
between the pet and terminal contexts exactly as in the current sealed model.
The drift incident writes the canonical v0.11 path
`telos/contexts/pet/notions/Pet.tel`, captures the drift token, proves mutation
is blocked, and reverts the same authenticated state.

The replay driver continues to execute commands without a shell and to replace
captured `@digest` and `@token` arguments. No broad shell execution or weaker
expected-output matching is introduced. `--compare` is restored as the
documented and CI path so the replayed files and release-tag set must match the
repository rather than merely complete successfully.

## Generated Integrations and Version Pins

All install snippets use the exact release `v0.11.0` and assets named
`telos_0.11.0_<platform>.tar.gz`. This includes the replay job, sealed-state
gate, Pages export, demo recorder, README bootstrap, and prompt bootstrap.

The files `.claude/skills/telos/SKILL.md`,
`.claude/skills/telos-challenger/SKILL.md`, and
`.claude/skills/telos-implementer/SKILL.md` are replaced byte-for-byte with the
assets embedded in the upstream v0.11.0 tag. Existing Claude settings remain
unchanged because their generated hook contract did not change.

The sealed workflow matches the v0.11.0 generator output. The demo replay job
is intentionally project-owned rather than generator-owned, but follows the
same checksum-verified installer pattern.

## Recording Pipeline

The current desktop tour proves the old intent catalogue and relation-filter
experience but misses the v0.11 preview's strongest interactions. Its
replacement tells one continuous feature story at the existing 1280×800
viewport:

1. establish project coherence and coverage on the Dashboard;
2. open the header's global search, type a human-readable query for
   `INT-0008`, show ranked results, and navigate from the selected result;
3. hold on the intent's canonical statement, then smoothly scroll to its
   canonical proved scenario;
4. open the Graph, type `INT-0008` into the graph finder, select the result,
   and show the focused node and populated selection panel;
5. open the Glossary, search for `Pet`, and hold on its typed consumer table.

The tour exercises controls through their accessible roles and labels rather
than CSS structure when a semantic locator exists. CSS selectors remain only
for stable application-owned anchors such as scenario IDs, the Cytoscape
canvas, and the selected-node panel. Keyboard entry is paced so search text
and ranked results are visible in the recording. Each transition waits for a
specific destination or rendered state instead of relying solely on fixed
delays; short holds remain only for viewer legibility.

The injected cursor adopts the v0.11 preview's blue/cyan brand: primary blue
for the pointer and cyan for click ripples. It remains DOM-owned,
pointer-events-free, and present on every route. The output contract remains a
1280×800 H.264 MP4 plus a 960-pixel-wide, 10 fps, full-palette GIF strictly
below 10 MB.

The recorder test is renamed from the 0.9 overview to the v0.11 feature tour.
It must assert the global-search result and navigation, canonical statement and
scenario visibility, graph-finder query and selected node, glossary search and
consumer table, and the ordered unique route sequence. Existing GIF dimension,
palette, invalid-input, and strict-size tests remain.

## Sealed State

No file under `telos/` is edited manually. After the external replay,
documentation, workflow, and agent-integration changes are ready, the installed
Telos 0.11.0 CLI runs `telos change reconcile --full --json`. This re-runs all
scenario proofs and executable constraints, regenerates `telos/telos.lock`, and
records `tool = "telos 0.11.0"` with a v0.11-computed specification digest.

The model files and application/test bytes are expected to remain unchanged.
Any unexpected model rewrite, coverage loss, failed constraint, or drift is a
hard migration failure and must be investigated rather than accepted into the
lock.

## Failure Handling

- A replay command failure stops at the exact prompt and command; the prompt or
  payload is corrected before proceeding.
- A first scenario run that does not produce a genuine red witness is not
  accepted as replay evidence.
- A changed test between red and green is rejected by Telos and must be restored
  before the replay continues.
- An owner, layout, or context-boundary diagnostic is fixed in the staged v0.11
  model; the check is not weakened and specification files are not patched
  directly.
- A replay/reference mismatch is treated as migration drift, not hidden by
  removing `--compare` or expanding its ignore list.
- A changed preview label, route, or interaction fails the recorder test at its
  semantic checkpoint; selectors are updated only after confirming the v0.11
  UI contract, never by removing the checkpoint.
- A generated GIF at or above 10 MB fails before publication. Timing or
  encoding is tightened without dropping the feature checkpoints.
- If v0.11.0 release assets cannot be downloaded in CI, the workflow fails
  closed at checksum verification.

## Verification

Verification is layered and must be fresh:

1. Run the existing replay against v0.11.0 before prompt migration and retain
   its flat-layout failure as the compatibility baseline.
2. Replay all prompts into a clean temporary Git repository with the v0.11.0
   binary and `--compare`; require all commands, expected failures, witnesses,
   file comparisons, and tags to pass.
3. Run `pytest -q` for the 17 application scenarios.
4. Run `python3 -m unittest tools.test_record_demo` and require the complete
   v0.11 browser tour plus GIF contract tests to pass.
5. Run `python3 tools/record_demo.py` with Telos v0.11.0, regenerate
   `docs/demo.gif`, and require the recorder's strict size check to pass.
6. Export the site with `telos view --export` into a temporary directory and
   require successful completion.
7. Run `telos status --json` and require `state = "coherent"`, full intent and
   scenario coverage, and no drift.
8. Run `telos check --sealed --json` and require a successful, diagnostic-free
   sealed check.
9. Search tracked text for stale `0.8.2` and `0.9.0` Telos pins; require none.

The migration is complete only when the clean replay and the checked-in sealed
repository both pass under the same v0.11.0 binary.
